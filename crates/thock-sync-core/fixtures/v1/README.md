# Vault sync fixtures, v1

The language-neutral corpus of `thock/specs/v34-vault-sync-api.md` §9.2. The Rust crate beside this
folder is one implementation; a Swift port is correct when it passes every file here. Generated by
`THOCK_SYNC_CORE_WRITE_FIXTURES=1 cargo test -p thock_sync_core --test fixtures`; verified by the
plain `cargo test -p thock_sync_core`. `gen-*` files come from a note × write × state matrix,
`hand-*` files state their exact output by hand.

## Case files (`<area>/*.json`)

```
before                 the note before the write, or null for a missing file
seed                   the expanded template handed to apply() for create_from_template, or null
write                  the write document (§7), or null for a roundtrip case
after                  the exact bytes apply() must produce
outcome                created | section_added | applied | kept_both | noop
effect_present_before  effect_present(before, write)   (skip when before is null)
effect_present_after   effect_present(after, write)
```

A runner, per case: assert `effect_present(before)`; `apply(before, write, seed)` must equal `after`
and `outcome`; assert `effect_present(after)`; then apply the same write to `after` and require the
text unchanged with outcome `noop`. For `write: null`, use an `append` with `heading: null` and no
`lines`: it must hand `before` back byte for byte.

## `hashes.json`

A list mixing `{"line", "line_hash"}` (§7.4 steps 1–7), `{"text", "heading_key"}` (V26 §5.1) and
`{"body", "section_hash"}`, where `body` is the section's body lines.

## `envelope.json`

`{"key", "nonce", "context", "plaintext", "envelope", "content_hash"}` with hex key and nonce,
base64 plaintext and envelope, and `context` as `{"kind":"file","path","blob_id"}` or
`{"kind":"write","client_id"}`. Sealing `plaintext` under `key` with that exact `nonce` must give
`envelope`; opening `envelope` must give `plaintext`; opening under another path, blob id or client
id must fail. One `{"key", "key_check"}` entry pins the key check. The nonce is fixed only to make
the vector reproducible: a real `seal` draws a fresh random nonce every time.

## `paths.json`

`{"syncable": [...], "refused": [...]}`, hand-written: `is_syncable_path` (§4.1) must accept every
`syncable` path and refuse every `refused` one. NFC is compared scalar by scalar, so
`notes/cafe\u0301.md` (decomposed) is refused while `notes/caf\u00e9.md` syncs.

## Where this corpus is stricter than the contract text

Decisions the implementation had to take; the contract will be amended to match.

- A section's **body excludes a closing thematic break** (`___`, `---`, `***`) and the blank lines
  before it. The shipped templates end every section with `___`; an append lands above it.
- Lines inside a **fence or front matter** never match `replace_line`, `remove_line`, or the
  contiguous-run check of `append`; a run may not span them.
- `replace_line` counts as **present when its target line equals `new_line`** (or `new_line` plus
  the marker); when the target is gone, when any body line equals either or hashes like `new_line`.
  Tick and retime keep the hash, so a plain hash test would call every such edit already done, and
  "any line equals" would refuse to tick the second of two identical lines.
- The **whole-file body** (`heading: null`) trims only blank lines; the end of the file is below a
  closing rule.
- `create` on an existing, different file (rule 3) counts as **present once the file contains
  `content`'s lines as a run**, so re-applying it does not append twice.
- A stale `replace_section` puts the marker on the **first non-blank** appended line.
- A write that **creates the file or adds the heading** reports `created` / `section_added` even
  when it then kept both or applied; the host needs the structural fact.
- `remove_line` on one of several identical lines **is not idempotent**: nothing in the write can
  tell whether it already ran. The phone sends one remove per tap and accepts this.
- `replace_line` and `remove_line` accept `heading: null`, meaning the whole file.
- A **front-matter block that never closes** is ordinary content.
